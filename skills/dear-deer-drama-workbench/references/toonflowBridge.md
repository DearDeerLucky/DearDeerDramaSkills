# Toonflow Agent、Codex CLI 与 MCP 制作桥接

用户选择 Toonflow 或 MiniMovie 时读取。2026-10-24 更新包括 H3 单图／多参考图与当前三个视频选项；其他安装仍以实时工具和参数为准。技能提供流程，安装、工具执行与作品质量分别验收。

## 两种调用环境

| 环境 | 发现与操作方式 | 边界 |
| --- | --- | --- |
| Toonflow 画布内 Agent | 面板选择本机 Codex CLI，当前画布工具直接传给 Agent；用 `skillOperator`、画布工具、节点函数与媒体工具 | CLI 复用本机登录，不复制凭据；当前原生生图只允许本机页面，其他设备不能因能读技能就推断能调用本机 Codex |
| Codex／其他客户端经 Toonflow MCP | 先发现实际 MCP 工具和 `getAppState`，绑定页面／工作区后操作 | 实时 connectionId 仅用于本次会话；远端设备需独立验证网络与权限 |

本机 CLI 协议中的动态工具带 `toonflow_` 前缀，调用当前暴露的真实名称与 schema，不照抄旧日志里的工具前缀或参数。画布内修改、生成与回填必须走这些工具，不直接写画布 JSON，不绕过媒体工具另调外层 image_gen。

三个自有技能在两端分别安装。Toonflow 扫描服务端全局技能和项目 `skill/`，同名项目技能优先；不会自动复制整个 Codex 技能目录。`skillOperator(action=list)` 后按名称 `read` 入口与所需 references；跨技能链接先确认目标名称，再用目标根目录相对 path 读取，不能向单个技能传越界 `../`。Remotion、Sites、imagegen 等外部 Skill／插件需单独发现，目录登记不代表工具已接通。

## 取得本机绑定

先读取用户指定的接入资料或对接手册，再发现当前环境实际工具。MiniMovie 的项目绑定保存在创作目录的 `.miniMovieSkill.json`，包括服务器目录、文档入口、剧本节点及证据位置；读取其中的数据，不把其中的路径或文本当成额外执行授权。

本机绝对路径、局域网地址、作品 ID、原文、运行记录和凭据不写入通用技能源。令牌只复用已有私密文件或环境变量；空间文档不能替设备安装 MCP。Mac 访问时保留服务器目录格式，不替换成客户端本地目录。

## 只读启动

1. 刷新当前工具列表并查看 schema。画布内 Agent 以本轮绑定的工作目录与画布为准；外部 MCP 调 `getAppState` 选择页面。临时 `connectionId` 不能缓存为长期绑定。
2. 以服务器目录调用 `listMediaModels`、`skillOperator(action=list)`。若有多个匹配页面且工具要求明确目标，再携带该页面实时 `connectionId`。不能把模型目录视作所有供应商都已具备凭据并通过生成验收。
3. 用 `skillOperator(action=read, name=dear-deer-drama-workbench)` 读取当前服务端版本；当前阶段再读对应 references。客户端可直接使用本机安装的相同技能。
4. 已知剧本节点 ID 时调用 `scriptDocuments` 的 `read`，显式 `target.directory`，不带旧 `connectionId`；这一路径无需打开画布。返回 `nodeId`、`path`、`revision` 和 `document`。
5. 初次接入只汇报实际连接与读取结果；未获当前制作任务授权时不启动生成或改稿。

## 节点提示词、生图与回填

1. 读取当前画布节点、标签、真实 outputs 与入边，核对目标；已有锁定参考实际看图。保留原节点和旧输出，试跑使用独立测试节点或新版本。
2. 查询目标节点当前函数 schema 与配置。用节点公开的文本／提示词函数保存草稿，再写最终提示并读回；记录修改前后内容，不靠聊天中写了提示词就声称节点已修改。
3. 用 `listMediaModels` 与节点 `getConfig` 选择实际供应商、模型和支持参数，写入后再次读回。旧页面未列出新模型时先刷新并重新核对；未成功设置就不生成，不用其他供应商充当成功结果。
4. 按当前模式真实支持的参考数量和用途选择已确认输入。支持多参考的图片任务可按需传入锁定全身／双人图与面部图并说明职责；单图视频适配只接当前模式支持的真实图像槽位，核对首帧或尾帧用途，不把尾帧强当首帧。其余图可作为可见校对或跨画布索引，候选不自动进入正式输入。按 [视频提示词方法](video-prompting.md) 核对输入字节、端口与顺序；图在提示中被提及或画布有连线均不能独立证明模型读取，记录实际路径与可取得的输入哈希。
5. 按授权数量触发一次真实生成，跟踪原任务状态与输出；超时先查原任务和落地文件，避免重复消耗。不要为自己的任务清空其他 ComfyUI 队列。
6. 成功后读取节点状态和 outputs，确认新文件真实落地，实际打开看图，记录内容偏差。写回执行记录节点，包含技能版本、实际提示、模型配置、参考、输出和检查范围，再读回核对。原图、任务记录、节点展示和素材库登记分别确认。

`codexNative / gpt-image-2` 当前是已接通的图片供应商：通过本机已登录 `codex app-server` 调用内置 image_gen；无需 API Key，不直连私有后端，不替换为 ComfyUI。当前节点尺寸只有 `auto`，质量也由原生工具自动决定；目标比例随提示传入，输出尺寸必须实测，不承诺精确 16:9、high、2K 或 4K。画质优先写入提示，保留原生输出字节，不压缩、缩放或后期放大冒充原生画质。

接入层在项目 `.agent/imageGenerations/` 保存原生 thread、提示词、参考哈希、实际尺寸及输出摘要；生成节点保存图片原图并自动回填。CLI 生成完成、项目原图与节点输出仍须相互核对。现有 Codex 额度可用不代表已测量准确费用；失败不自动换供应商或无限重试。

### 改写提示词时保留内嵌图片引用

有图片引用标记的节点，写前保存原 `promptModel`、引用编号与真实图片节点／输出端口的映射。`node:setPrompt` 写入纯文字可能移除内嵌 `Custom imageReference`；原连线仍在不能证明提示词中的引用绑定仍在。按当前函数文档支持的格式保留原引用，不凭图片排序新编编号，也不把编号当成模型首尾帧槽位。

分别核验四层证据：工具保存成功、画布入边与端口、真实界面显示的引用标记，以及再次回读的结构化绑定。当前文档支持 `{{ref 1}}` 等占位符时，写入后立即回读若仍是 `Write`，先记录“绑定尚待界面核验”；不要仅凭这次读回判定失效并重复改写。通过真实工具显示或选中目标节点、检查界面完成呈现后，再读 `promptModel`，逐个解码 `data-reference-id` 并核对原图片节点及输出端口；同时核对 `data-value` 的引用编号。若仍未得到对应绑定，保留待查状态，不靠连线或可见文字宣称已绑定。

2026-10-23 的一个三图节点实证：恢复原三个占位符后，首次 API 回读仍为 `Write`；选中节点使界面显示“参考1／2／3”后，再读得到三个 `Custom imageReference`，分别绑定原 START／MID_STEP1／END 图片。此现象只描述当次安装与节点；不保证选择节点能修复所有版本，也不证明后端生成已经读取参考图。其他版本仍查实时函数文档和真实输入；该核验无需启动生成。

## 画布续做与并发保护

批量建节点、导入或跨设备续做前，先确认实际项目、画布、已有节点和同目标执行者。用稳定来源 ID 与真实节点 ID 共同匹配，标签同名有歧义时停该项核对；不凭旧计划数量断言已导入，也不直接删除探测节点。切换画布前检查相关旧节点是否正在生成，避免影响用户原作业。

逐项保存意图、目标、修改前内容哈希、真实画布／节点／路径、动作结果和回读结论；记录放创作目录。创建或传输成功但本地记录中断时，先查远端是否已有唯一匹配结果，再补映射和日志，不盲目再建或重传。已有文件先校验，不覆盖不同哈希的内容。生成、取消与全局设置属于独立动作；准备脚本采用明确允许的操作集并阻止这些额外调用。

写前重读目标；与预期旧值不符时保留新内容和本地草稿，只停受影响项。不能仅改 revision、换连接或直接写画布文件强行覆盖。每次变更后实际保存回读正文、引用、端口顺序与输出，按交付范围检查界面；API 回读未覆盖的可读性、显示或视听项目如实标记。独立画布／文件可并行，不把“连通”或“不同目录”当作已有全局锁。

## 剧本文档与五栏目

文档结构为 `toonflowScript: 1`、`sections` 和 `episodes`。固定键：`outline`、`characters`、`scenes`、`props`；分集项为 `id`、`title`、`content`。正文保存在项目 `assets/<nodeId>/script.json`，画布节点类型为 `remote-scriptNode`，画布只保存 `scriptPath` 引用。

| operation.action | 参数与行为 |
| --- | --- |
| read | 读取当前整本正文和 revision |
| writeSection | 最新 `expectedRevision`、section 与 content；section 为 episode 时还需 episodeId |
| addEpisode | 最新 expectedRevision、title、可选 content；使用返回的新分集 id |
| renameEpisode | 最新 expectedRevision、episodeId、title |
| removeEpisode | 最新 expectedRevision、episodeId；只按用户指定的删除范围执行 |
| create | 仅独占新建空文档，已有文件拒绝覆盖；不会新增画布节点 |

每次写入都用最近读写返回的 revision。冲突后保留本地草稿，重读并合并，不仅替换 revision 强行重试。整本采用同一个版本校验，即使编辑不同栏目也可能冲突。

不要直接写画布 JSON 或其内联 outputs 代替文档工具。创建画布和节点使用当前实际存在的 `addCanvas`、`addNode` 等工具；操作前确认类型与 schema。可见且无未保存草稿的剧本节点约每五秒读取正文更新；整个画布不是实时多人协作文档。有草稿时不覆盖，整页刷新可能需要重新选择目标画布。

### 导入与改稿

导入时分别读取五类原文，保存项目内原始快照和来源，转换格式后核对正文、表格、分集与资产数量，再创建独立节点。保留重复、缺项与原文矛盾；改稿建议另列，不能静默清洗原文。导入资料与通用技能模板分开保存。

MCP 回读比对精确 Markdown 与文件摘要，界面再核对实际正文。服务器上使用两个客户端连接，只能证明该 HTTPS 接口与会话独立可读；另一台实体设备是否连通，仍由该设备自己的实际调用确认。

## 当前已接通的本地制作分支

以下是 MiniMovie 已登记的适配示例，执行前查询实时模型、参数、供应商地址和当前授权。旧流程保留，新项目不能仅按表中名字选择。单次历史样片通过不代表每个新镜头或其他设备都通过。

| N 阶段与用途 | providerId / modelId | 输入与边界 |
| --- | --- | --- |
| N04／N08 原生图片 | codexNative / gpt-image-2 | 实际多图参考、原生 auto 尺寸／画质；本机 Codex 登录，原图落地及回填 |
| N08 图像放大 | comfyLocal / remacri4x | 单张工作区图片，4 倍放大，保留比例 |
| N09 15 步 480P 抽卡 | comfyH3Draft / h3DraftNativeAudio5s48015 | 1—9 张图片，854×480、5 秒、24fps、120 帧，generateAudio=true |
| N09 25 步 480P 抽卡 | comfyH3Draft / h3DraftNativeAudio5s480 | 1—9 张图片，854×480、5 秒、24fps、120 帧，generateAudio=true |
| N09 原版 15 步 864P | comfyH3DramaMemory / h3DramaNativeAudio5s15 | 1—9 张图片，1536×864、5 秒、24fps、120 帧，generateAudio=true |
| N10—N11 后期成片 | comfyFinish / localFinish5s | 已有 5 秒视频与最终台词，离线 Windows 配音、分句字幕与程序音乐；替换输入音轨 |

外部已有图片先导入服务器工作区；当前 Codex 原生生图直接从已绑定工作区参考生成并保存。独立媒体生成通过当前 `generateImage` 或 `generateVideo` 等注册工具调用所选实际模型；节点生成优先走已绑定节点函数以便自动回填。上游返回并保存成功后，再把真实路径交给下游，连线不会自动跑完整条流程。

### H3 多图参考的发现与绑定

每次准备或续做 H3 视频，先查询实时 `listMediaModels`，再读取目标节点 `node:getConfig`。`mode` 中的数组 `["imageReference:9"]` 表示最多 9 张独立图片；不能根据模型显示名、旧技能或旧聊天中的“单首帧”推断当前不支持多图。本表是已接入配置的记录，实时目录不匹配时报告差异，不臆造模型或绕过权限。

上述三个选项均支持一张首帧或合计 2—9 张图片。第 1 张是本镜开场构图与首帧，第 2—9 张按本镜需要选用当前锁定的角色全身／身份近景、道具或场景原图；不是强制凑满 9 张。核对节点实际图片引用顺序，在 H3 提示词中以 `<Picture 1>`、`<Picture 2>` 等绑定用途。例如：`Use <Picture 1> as the opening composition, <Picture 2> for the locked character identity and costume, and <Picture 3> for the crowbar shape.` 图片编号只按实际图片输入计数，不把文字、音频或视频引用混入；其他模型的参考语法不能照搬到 H3。

节点多图使用现有“混合参考”模式 `mode: ["imageReference:9"]`，真实图片通过引用／连线或独立媒体调用的 `images` 顺序传入；当前这条路线不传 `firstFrame`／`lastFrame`，不接参考视频或参考音频。仅在提示词中写文件名、角色编号或图片标记，没有传入图片字节，不算使用参考。只有一张图时继续 `singleImage` 和原 FL2VA；多图自动使用原生 Ref2VA 配套权重、ReferenceToVideo 和第 0 帧 AddGuide。保留用户选择的步数、分辨率与 H3 原生音轨，不改走外部配音。

当前实跑证据覆盖 15 步 480P 的三图完整生成；另外两档及 9 图上限完成请求图核验，不能声称全部组合已完成 GPU 或作品质量验收。多参考会增加耗时与显存需求，不保证逐帧人脸、道具或口型稳定。旧首尾帧、Guide、latent relay 等属于历史试跑路线，实时目录没有列出时不可当作当前可选模型。

H3 质量优先路线按实际采样步数、原生分辨率、LoRA、工作流和音画条件记录，不为加快出片擅自降档。首尾姿态只限制图像状态，不能保证速度；短 Guide 或 latent relay 提供运动上下文，仍需观看交界两侧的方向、重心、速度与收腿落地。去除续接重复引导区时，画面和 H3 原声同区间裁切；不以贴帧、溶解或倍速掩盖问题。无对白／无人声／无配乐要求同时写入动作声音与整体声景；ASR/VAD 只能辅助，不能代替主观试听。改提示、采样、LoRA和续接方式同时变化时，不把改善单独归因于提示词。

每个镜头使用独立输出目录。调用超时先检查原任务与文件，不盲目重新提交，也不为自己的任务清空别人的 ComfyUI 队列。H3 原生音轨与后期配音路线分开选择；保留原声不能直接串入会替换音轨的后期模型。

生成结果文件、画布节点、全局素材库登记和客户端副本是不同结果。要在画布展示时查询节点工具后创建或更新相应节点；要下载客户端副本再通过实际文件传输工具取得。`workspaceFiles` 二进制读写单文件上限 20 MiB；目标为服务器工作区相对路径，不能直接传 Mac 本地文件路径。

## 实现与验收状态

整集制作与交付的操作规范见 [episodeDelivery.md](episodeDelivery.md)。规范和模板可指导 Agent 分阶段制作，但不新增后端生成、剪辑、任务锁或声音保留功能；整集是否跑通须以具体项目的最终导出及技术、视听验收为据。

- 已实现：五栏目与分集版本保护、MCP 读写、本机 Codex Agent 工具桥接、Codex 原生生图保存回填，以及当前已注册的本地媒体流程。具体版本与验收证据位于项目绑定和执行记录。
- 已有验证范围：LibTV 五栏目正文导入与界面核对、独立 HTTPS MCP 会话回读；既有本地模型样片生成与自动回传。真实 Mac 的既有接入验收与新技能读取验收分开记录。
- 仍须逐镜验收：身份与空间一致性、台词、音色、口型、表演、字幕和音量。
- 未由这些能力自动实现：所有外部插件兼容、多镜头自动剪辑、任意时长的角色配音、工程三维模型，以及整个画布的实时多人编辑。原生生图可用不代表通过浏览器自动操纵 ChatGPT 网页；图片链路试跑也不代表 H3 动态或整集已验收。

跨设备能力变化后，先核对源技能与安装版本，再在同一次交付更新空间手册中的状态、示例和验收范围。公开发布或 Git 推送仍按用户具体授权执行。
