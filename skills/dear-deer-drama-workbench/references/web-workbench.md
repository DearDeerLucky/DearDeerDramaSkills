# 可复用网页资料工作台

由已完成的视频前资料网页抽取，保留原有能力，不固化它的剧情、角色和素材数量。默认本地静态网页；作品内容和每轮选择由用户决定。总工作台 N00—N15 合同保持原样，网页只是跨节点视图。

## 已有能力与使用入口

内置 [../assets/preproduction-web/index.html](../assets/preproduction-web/index.html)、配套样式、逻辑和空白数据。支持：制作规格、按顺序的十二个视频前节点、待补／已有候选／已选用状态、实际图文音视频预览、添加与移出资料、明确当前文件版本、本机保存、按需新增资料位、备注、缺项筛选、镜头起止参考、视频启动检查与任务卡、清单导入导出、空白项目。新增角色五方向与多轮暂选区，导出选择记录给创作对话。

用户说“把这些资料放进网页”“做一个等待添加的模板”“给五方向比较页”时启动；只讨论角色文字方案时不强制网页。需要进一步设计或公开部署时读取当前 Sites Skill；本地模板可以直接用，不依赖外部账户。

用 [../scripts/build_workbench.py](../scripts/build_workbench.py) 构建，不安装依赖、不访问网络、不生成媒体。示例：

```text
python3 <本Skill目录>/scripts/build_workbench.py --output <独立网页目录> --standalone
python3 <本Skill目录>/scripts/build_workbench.py --manifest <已核对清单.json> --output <独立网页目录> --standalone
```

已有生成目录需要明确更新时加 `--refresh`，只接受有本脚本构建回执的目录。保留旧作品原件和版本；需要完整回溯时先复制旧网页输出。默认不覆写非空未知目录。

## 数据清单

输入与模板 `project-data.js` 相同：顶层 `version:1`、`assets`、`projects`。从模板的空白数据取结构，按本轮实际素材填写，不把初始占位当已准备。

`assets` 是 ID 到资产对象的映射。每个对象有 `kind`（document/image/audio/video/text/data）、`name`、`version`、`note`，加实际本地 `source` 文件路径，或本轮已写好的 `text`。相对路径按清单文件目录解析；不要放外部链接、虚构路径或指向尚未生成的文件。脚本核对输入、复制文件并记录原路径和摘要；缺文件立即报错，转回等待添加位后继续。

`projects[]`：稳定 `id`、`metadata`（作品名、集号、目标秒数、画幅、语言、表现形式、画风、总集数）、`nodes[]`、可选 `characterDesign`。未知规格留空；沿用用户已选规格，不从分镜页排版推断。

`nodes[]` 保留十二个视频前节点：N00规格、N01故事、N02剧本、N03资产清单、N04角色、N05场景、N06道具、N07分镜、N10声音、N08关键帧、N14连续性、N09视频启动。每节点有 `id/title/description/kind/depends/items`，分组型带 `groups`。节点编号跟总流程一致；显示顺序服务视频前准备，不重新编号。

`items[]` 有 `id/title/kind/required/defaultAssets/note`；所属角色、道具或镜头用 `group`。没有资料时 `defaultAssets:[]`、`initialSelected:false`。有文件也不自动选用；仅已有明确用户选定记录才能设置 `initialSelected:true`。

同一要求的替代候选可用同一个 `choiceGroup`，启动只要求组内选用一个，不要求把五方向全选。限定本批的资料位可用 `shotIds:[...]`；本集其他镜头的资产不阻塞首个样镜。新增版本必须重新选用当前文件，不能把一组多个不同版本全当同一母版。

`N08.groups` 描述实际镜头 ID、动作、秒数估计和是否需要结束帧，`N08.items` 以 group 指向镜头，给起／止独立资料位。多格分镜图不能替代独立镜头关键帧。

`characterDesign` 示例结构：

```json
{"characterId":"CHAR001","title":"角色设计 · 多轮选择","expectations":["已给期望"],"rounds":[{"id":"R1","title":"五个整体方向","options":[{"id":"D01","title":"具体结构名称","detail":"脸、头发、衣装、材质位置、配件功能、适配与代价的具体文字","assetIds":[]}]}],"locked":["已选定的设计项"]}
```

真实 R1 按角色专用 Skill 填满 D01—D05；空白模板的五格明确是等待设计。R2脸发、R3衣装配件、R4完整复核按当前阶段填入实际候选。混合要求写备注。网页暂选不会自动修改设计卡或授权生成；用户把导出记录交给Codex时按其最新请求核对并续做。

## 保存、导入、备份与单文件

状态与备注用 localStorage，用户添加的文件用当前浏览器 IndexedDB。记录真实当前版本。刷新后检查资料仍存在；跨浏览器／设备／不同来源地址不承诺自动共享。用户的原件始终另行保留。

清单JSON保留状态、备注、文件名、选项与版本引用，不含上传文件二进制。原网页素材已复制进网页目录；换设备交付整个目录／素材包，或输出包含原素材的单文件HTML。后续从网页添加的文件不会反向写入已生成HTML；重新打包需使用原件更新清单。

导入检查格式与项目ID，缺附件显示需要重新添加；不能因导入了“已选”字符串就把不存在的文件当现成资料。导入后连续性与试听检查重新为未核对。导出选择记录是暂选与要求，正式母版仍以创作对话的用户选择和实际图像检查为准。

## 视频启动与验收

按本批检查：规格、基础素材实际版本、起止帧、对白与音画路线、工具数量和成本、人物空间道具复核。后期配音路线不要求在图生视频前把最终音轨全部生成；同期音画路线需要对应最终对白音轨及试听。工具填写和网页勾选只是计划／用户记录，不证明模型可调用、图像通过或视频已经生成。

保存初版后至少检查一次：空位、文稿预览、添加真实图片、版本切换、暂选与备注、刷新、本机附件恢复、导出后导入、缺附件反馈、首样镜与整集范围、宽屏与窄屏布局。只检查本次新增或实际受影响能力，不重复整套制作测试。

用本地服务器或可用的文件预览工具展示；网页打开不等于资料齐备。交付入口、实际已有／待补统计和本轮验证范围。公开部署、账户绑定或实际媒体生成均按用户明确范围另行执行。
