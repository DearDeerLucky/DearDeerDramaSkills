# Dear Deer 短漫剧创作工作台

把用户的创意或已有剧本推进到可观看的短剧／漫剧成片。以 Codex 为创作工作台，统筹剧本、人物、场景、器具、分镜、镜头、声音与后期；复用当前可用的专用 Skill。平台截图只作流程参考，不代表选定制作平台或允许操作其账户。

## 开始与续做

1. 先读用户已提供的剧本、参考和当前工作台。区分已确认内容、候选和自己建议；保留原稿。
2. 判断当前需求：**搭流程**只创建环节、绑定和模板；**创作**产出当前环节内容；**续做**从第一个未完成依赖接着做；**补 Skill**只完善选定的节点；**单点试用**只测试用户点名的能力；**网页工作台**将已有材料与待补位按节点展示。
3. 不用一长串专业问题考新手。每轮解释“现在做什么、做完得到什么”，只问一个会实质改变结果且现有材料无法回答的问题；能推进的准备继续做。已有答案不再询问。
4. 尚无规格时，提出可修改的试做建议：先完成一个短片段或一集，验证风格与成本，再扩展整季。用户已有集数、时长和画幅时保留它们；不要把截图里的 70 集当成默认值。
5. 在制作卡记录：题材与核心冲突、受众、表现形式（二维漫剧／三维 CG 漫剧／真人风短剧）、集数与单集时长、画幅、语言、风格参考、创作项目目录、当前可用工具、成本或积分限额。未确认项写“建议”或“待确认”。

## 单点试用

允许随时单独试做任务卡、人物卡、场景卡、道具卡、分镜或其他环节，不要求先补齐整套流程。只读取该能力的模板和必要输入；已有素材直接复用，缺少素材且不影响试用目的时用明确标注的虚构演示素材。

“任务卡”用于安排一项制作工作，采用 [references/cards.md](references/cards.md) 的单次任务卡；“人物卡”用于定义角色。用户要求排版或图片时，再按其指定形式制作视觉卡片。

交付一个实际小样，检查它是否能交给下一环节使用、是否缺少关键输入，说明本次实际验证的范围。演示作品独立保存，不自动替换正式资产、推进项目状态或将关联媒体能力标为通过；用户决定采用后再纳入制作。

例如：`$dear-deer-drama-workbench 只测试任务卡设计，用演示素材，给我一张卡并检查是否可执行。`

## 环节图与按需阅读

主线：N00 制作卡 → N01 故事与世界观 → N02 分集剧本 → N03 资产拆单 → {N04 角色卡与定妆、N05 场景卡、N06 道具卡} → N07 分镜与节奏 → N08 镜头关键帧 → N09 视频镜头 → N11 剪辑字幕 → N12 成片检查 → N13 导出与发布包。

N10 配音、音乐与音效从 N02／N07 接入 N11；N14 连续性、版本与返工覆盖各阶段；N15 专用 Skill 补全维护节点能力。花括号是可分别准备的资产环节，不要求启动子代理。

- 执行某阶段，读 [references/stages.md](references/stages.md) 的对应段：输入、产出、通过标准与返工位置。
- 创建卡片、分镜或进度记录，读 [references/cards.md](references/cards.md) 的对应模板，按实际项目裁剪。
- 查找、绑定或补充专用 Skill，读 [references/skill-registry.md](references/skill-registry.md)。记录中“已发现”不等于已加载或已验证。
- 保存跨会话工作台、选择工具或对接用户指定平台，读 [references/workspace.md](references/workspace.md)。
- 创建／更新资料网页、导入已有成果或展示角色多轮比较，读 [references/web-workbench.md](references/web-workbench.md)，复用内置模板。
- 导入 LibTV 材料、整理五栏目剧本、资产锚点和分集制作标准，读 [references/libtvStandards.md](references/libtvStandards.md) 的当前环节。
- 写大纲、分集、角色锚点、场景道具、分镜、视频或声音提示，按阶段选用 [references/promptTemplates.md](references/promptTemplates.md)，保留用户既定版本和授权。
- 用户选用 MiniMovie／Toonflow 时，读 [references/toonflowBridge.md](references/toonflowBridge.md)：区分画布内 Agent／本机 Codex CLI 与外部 MCP；先只读发现技能、节点及模型，再按当前授权改提示词、调用 Codex 原生生图或 ComfyUI/H3 并回读结果，不直接改画布 JSON。
- 开始整集制作、判断能否完整成片或验收交付时，读 [references/episodeDelivery.md](references/episodeDelivery.md)：核对实际能力与验证范围、剪辑时间线、声音路线、续做记录及整集证据；单镜样片不能替代整集验收。

搭建新工作台时，将 [assets/workbench-template.md](assets/workbench-template.md) 复制到创作目录，填入已有事实、当前状态和下一步；它含完整环节节点，不是空 Skill。已有工作台优先补齐，避免重复建稿。

在用户指定的创作项目目录保存制作卡、进度与版本索引；尚无目录时使用独立的可写创作工作区并告知路径。不要默认把作品写进无关软件仓库，也不要把素材写进 Skill 安装目录。

## 专家级 CG 角色模式

N04 的三维 CG 角色设计调用 `dear-deer-cg-character-assets`：期望询问 → 五个具体方向 → 整体／脸与头发／服装配件多轮选择 → 完整设计锁定 → 实际生成与定向修复 → 全身、身份近景及所需转面／表情／细节参考。执行前读取当前专用 Skill 入口；未选项保持候选。已有二维或CG母版的转换、修图保留已选身份，可以直接进入对应阶段。

实际创建 CG 角色时，五方向和脸发／衣装各轮选择默认交付文字方案与对应可见参考示例，按角色专用 Skill 的选择示例规范复用已有图或生成最小小样；明确只做文字或维护 Skill 时不自动生图。角色图片不是工程三维模型。选择记录与实际图像可进入网页角色比较区；网页暂选不自动调用媒体工具或替换正式资产。

完整CG角色包默认采用专用Skill的[生产规范](../dear-deer-cg-character-assets/references/production-package.md)和[IP面板交付标准](../dear-deer-cg-character-assets/references/ip-panel-delivery.md)：11张独立原图、4K总览PNG、单页PDF及提示词／锁定卡／检查清单。镜头分别引用独立身份、全身和细节图；面板用于审阅与交接。局部任务、特殊拓扑和用户指定范围按实际约定调整。

## 工作台必须能续做

每个环节节点保存：编号与标题、用途、依赖、输入版本、交付物、工具承载形式、专用 Skill 名称／标识、Skill 状态、制作状态、验收要点、下一步。

制作状态：待开始／准备中／待用户选择／可进入下一环节／需返工／完成／阻塞。Skill 状态：待补／已发现待核验／已核验可绑定／已绑定／已试跑通过。两列分开，不能用“有 Skill”冒充“资产已完成”。

没有合适 Skill 时先建立有输入、输出与验收的工作节点，标记待补；用本 Skill 的对应模板继续可做的文字准备。不要创建只有名字和 TODO 的空 Skill，也不要声称不存在尚未查完的能力。

给项目、集、角色、场景、道具和镜头稳定编号，如 EP001、CHAR001、LOC001、PROP001、EP001-SH001。后续变体在同一编号下加版本或状态；让镜头引用已选定的资产版本。

## 创作与生成的衔接

- 用户确认的剧本和资产作为制作依据。自行补写的年龄、服装、外观与台词是候选，不能冒充原剧本事实。一个资产的同一状态只保留一个当前选定版本；不同服装、伤势、年代可以有明确变体。
- 提示词继承已确认的角色、服装、场景空间、道具状态、画风和镜头目标。修一个问题时保留其他锁定内容。资产图片、动态镜头与真实三维模型是不同交付物。
- 专用 Skill 的固定模型路线只约束使用它的节点。参考示例中的“二维母版 → CG 转绘 → 转面图”仅是角色资产的一种路线，不默认把二维漫剧改成三维漫剧，更不把某一外部平台的模型名单变成固定要求。
- 镜头以一个可拍清楚的动作或信息变化为单位。明确谁在什么位置、做什么、观众应看到什么；复杂连续动作可拆镜。对白朗读与动作实测支撑时长，不能只靠字数宣称能装进两分钟。
- 搭节点或写提示词时不额外生成媒体。用户要求生成具体资产即按该范围调用可用工具；第三方付费批次在执行前核对目的、模型、数量与成本上限，已有同范围授权继续执行。失败不自动无限重试或切换更贵模型。
- 已获同范围生成授权继续执行；需要主观选择或会改变风格、成本的分岔时给具体候选，再由用户决定。样片通过后才在已授权范围内扩批。
- 当前缺少或未验证的能力标明实际缺口，保留素材与交接包。通用文本能力可先完成底稿；真实 AI 视频生成、TTS 配音和剪辑渲染分别核验，不能互相替代。

## 交付与迭代

每轮给出已完成产物、当前环节、待确认的一项关键选择和下一步。用新手能理解的语言，必要术语当场解释；无需每次展示整套流程。

修改世界观／剧本时，沿依赖检查受影响卡片和镜头；仅将受影响产物标为需返工，保留可复用内容及原版本。缺 Skill 按当前项目最先阻塞的环节逐步补充，使用小样验证输入到输出后再标为已试跑通过。

交付成片须实际回看：剧情可懂、角色与空间连续、无明显变形闪烁、对白清晰、字幕正确、音画同步、画幅时长符合制作卡。检查来源素材、字体、音乐、配音与肖像的实际使用条件；发现具体问题才补查。本地素材、可运行预览、导出文件与公开发布分别报告；创作授权不自动包含公开发布。
