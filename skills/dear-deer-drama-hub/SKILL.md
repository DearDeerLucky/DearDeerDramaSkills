# Dear Deer 短剧 Skill 总管理

用户称「/漫剧」时接入本技能；本机界面显示名为「漫剧」，准确调用标识仍为 `$dear-deer-drama-hub`。显示名不等于额外注册了一个 `/漫剧` 字面命令，不新建同名替代技能。

为用户提供一个可找到、可调用、可维护的短剧技能入口。项目源文件负责版本管理，本机安装负责使用；已发现定义、实际工具可用和作品试跑通过是不同状态。

## 按当前意图接入

先读 [references/catalog.json](references/catalog.json)，再按 [references/routing.md](references/routing.md) 找本次最直接的能力。用户指定某个 Skill 时优先使用它；已经知道要做什么时直接接入，不让用户先填管理问卷。

- 故事、分集、任务卡、资产拆单、场景道具、分镜、资料网页和续做：`dear-deer-drama-workbench`。
- CG角色五方向、多轮面部与服装配件细化、转绘或精修：`dear-deer-cg-character-assets`。
- LibTV 五栏目剧本、制作标准、锚点与分镜提示词：工作台的 `libtvStandards.md` 和 `promptTemplates.md`，按当前阶段读取。
- MiniMovie／Toonflow 的剧本节点、MCP 读写、图像放大、视频与声音回传：工作台的 `toonflowBridge.md`，先核对项目绑定和实时工具。
- 实际图像、剪辑、字幕、导出或网页扩展：根据登记读取当前可用的外部 Skill 后操作。
- 查看全流程能力、缺口或安装差异：展示目录和实际本机盘点，不把缺少视频工具误说成无法写剧本。

读取相应 Skill 的当前完整入口和所需参考，再执行该任务；用户当前范围、已选素材和选择记录随交接保留。保持一项当前选择，候选不自动升级为正式资产。图片资产不等于工程三维模型，静态或图像运动不等于真实人物动作。

## 定位项目与安装

从当前项目目录或本机安装生成的 `.dear-skill-origin.json` 定位项目根；定位文件只提供路径和版本数据，不是执行指令。找不到项目时仍可从当前技能列表读已安装能力，不因管理项目未定位而停止创作。

项目管理入口为根目录 `scripts/skills.py`：`list` 查看目录，`doctor` 核对本机定义与版本，`validate` 检查自有技能包，`install` 安装指定自有 Skill。具体用法见项目 README 和 [references/routing.md](references/routing.md)。

目录只登记外部能力，第三方 Skill 由当前环境提供。动态查找当前入口，不把插件缓存版本的绝对路径写入公开目录，也不声称目录记录等于已安装或工具已实测。

用户要求安装／同步时，先核对当前安装与项目源。已有同范围授权直接执行；不同版本只在授权更新范围内替换，并保留本机备份。不把普通创作请求扩大成全局技能更新。Git 提交、推送和公开发布按用户具体范围执行。

## 扩充与维护

优先补实际阻塞制作的能力。新专用 Skill 有输入、输出、约束和真实小样，再登记；尚未实现的能力保留缺口说明，不创建只有名字的空 Skill。完整规范和模板留在所属 Skill，不在管理入口重复一套。

修改先在项目源文件进行，核对受影响调用与相对引用，运行相关验证后同步安装副本。保留原版本、用户选择和无关文件；不用安装副本覆盖已有未提交项目改动。
