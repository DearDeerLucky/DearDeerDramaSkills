# IP角色面板与最终交付标准

完整角色图片包的默认终点是独立原图、IP总览面板及可续做的交接资料。用户指定其他尺寸、版式、格式或较小范围时遵从本次约定并在清单说明差异。

## 面板内容与版式

默认横版16:9、3840×2160 PNG，另交同版式单页PDF。所有栏目取自本角色同一版本的已检查原图：

| 区域 | 必含信息 |
|---|---|
| 标题 | 角色名、CHAR编号、版本；项目和已知身份／年龄按已给事实填写，注明制作参考状态 |
| 身份 | 足够大的中性身份近景、简短可观察的脸发气质特征 |
| 全身 | 正面、自身右侧面、背面；清楚标明方向，同尺度呈现，头顶和足端完整 |
| 表情 | 中性及默认五种派生表情，标签与实际文件一致，能比较眉眼口角 |
| 配色 | 主要衣装／发色／配件色块和名称；注明视觉参考，不能冒充精确材质测量值 |
| 细节 | 衣装与材质、装备与连接两组可读细节；不存在的装备不补造 |
| 页脚 | 总览用途、实际生成引用独立原图、必要的版本／检查范围说明 |

推荐上排身份近景、三向全身、两组细节，下排六种表情；可按特殊体型调整，不让装饰排版挤掉核心图像。采用可读中文字体、清楚的字号层级、留白和图间隔；不得遮挡关键五官、服装、手足或配件。长角色名与多语标签要按实际文本适配，不套用固定宽度后溢出。

## 原图与排版方法

- 先生成、查看和修复独立原图，再使用原生文档／矢量／页面排版工具组合；不让图像模型重绘整个最终面板，以免脸、左右、衣装或文字重新漂移。
- 面板可按框等比缩放。不能拉伸、镜像、重绘或裁掉必要结构；裁切边界只在该栏目明确需要的局部内使用。排版不能掩盖原图缺陷。
- 原图文件保持不变。PDF可嵌入符合面板展示分辨率的图像以控制体积，不能覆盖原图或将面板裁图冒充独立高清原图。
- 使用PDF工具时先读取当前可用PDF Skill，并依其导出、渲染和查看要求验收。所需排版／PDF工具不可用时保留原图与可编辑排版源，明确尚缺PDF，不能把改扩展名或提示词当成已导出文件。
- 排版源保存在创作项目，记录字体与工具依赖；不在通用Skill源码中提交某次作品、字体私有副本或本机绝对路径。

## 最终核验

1. 打开最终PNG，检查4K像素、中文、标题、方向、栏目、边界、颜色标签和全部图像是否完整可读；PDF须实际渲染后检查同样内容，核对单页及实际文本。修排版后查看最新导出，不能只看旧预览。
2. 对照锁定卡及独立原图检查版本和左右。面板中的“中性”与身份近景是同一原图；三向中的“正面”与母版是同一原图。表情和细节不混入旧版、弃选或未检查图。
3. 打开所有原图并记录实际尺寸；排版前后核对原图SHA256不变。技术文件可读与可见内容通过分别登记，遮挡、微小结构及未展示部分不计通过。
4. 检查所有清单与提示词引用可解析；打包后验证压缩包CRC和成员摘要／数量，确认索引指向当前交付。不得混入令牌、私钥、缓存或与作品无关的运行配置。
5. 输出的结论只涵盖静态角色图片参考和面板。它不证明精确正交建模、绑定、口型、动作或整集镜头已通过。

## 文件和便携清单

建议目录如下；实际命名可适配项目，但角色ID、版本和各文件职责必须稳定。

```text
CHAR编号_角色名/
  版本_角色资产包/
    01_front.png ... 11_equipmentDetails.png
    presentation/角色名_IP角色面板_版本.png
    presentation/角色名_IP角色面板_版本.pdf
    prompts/实际生成及修复提示词.txt
    资产包索引.md
    角色设计锁定卡.md
    检查记录.md
    交付清单.json
  历史候选与原始参考/
  排版源与本机执行记录/
```

索引标明当前母版、身份近景、各视图的职责、面板入口、生成时怎样选参考，以及未覆盖的验证范围。锁定卡和检查记录使用[角色记录模板](../assets/character-design-record.md)，不用面板上的短文替代完整记录。

便携`交付清单.json`至少包含：

- `packageId`、角色ID／名称、项目、版本、创建／更新时间、交付范围、用户选择或委托采用依据。
- `fullBodyMaster`、`identityReference`及各补充图的职责；`assets`逐一列独立原图的ID、用途、相对路径、实际尺寸、SHA256、输入参考、采用与检查状态。
- `presentations`单列PNG与PDF的路径、尺寸或页数、摘要、来源原图、确定性排版方法与检查范围；不把它们计入11张原图。
- `prompts`及`documents`列实际文件；生成工具和实际可用参数另记。文件摘要、尺寸、检查结论以实际测量／查看填写，不预填通过。

包内路径以包根目录为基准，源引用使用资产ID或相对路径；本机绝对路径、临时工具响应和详细执行日志放内部记录，不作为跨设备交付依赖。清单无需嵌入自身摘要，压缩包摘要保存在包外分发记录，避免循环依赖。

## 压缩包与跨设备交接

默认给完整ZIP，包含当前独立原图、面板PNG／PDF、提示词和资料。历史候选保留在创作目录，不与当前母版混装。更新时保留旧包并生成明确新版本／含面板的新包，不静默覆盖已经分发的版本。

按当前实际传输上限决定是否分包，不固化某个平台的固定限制。完整包超限时按功能拆分，例如A转面与细节、B表情、C面板；每包保留所需索引／清单，记录各包体积、摘要与合并顺序。若C包含新版索引，明确最后解压C覆盖说明文件；所有原图摘要保持一致。

只有用户要求进入Toonflow时才增加远程操作，按工作台[Toonflow桥接](../../dear-deer-drama-workbench/references/toonflowBridge.md)发现实时MCP schema：创建／选择项目与画布，通过文件传输工具上传，再经已注册的图片节点函数绑定真实路径。项目文件、画布节点、全局素材库和客户端下载是不同结果，不互相冒充。保存项目目录、画布／节点ID和文件摘要回读；未在另一台实体设备执行的读取，不能声称该设备已实测。
